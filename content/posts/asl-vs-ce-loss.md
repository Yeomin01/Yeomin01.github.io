유해콘텐츠 분류 (CENSURE / DISCRIMINATION / SEXUAL / ABUSE / VIOLENCE / CRIME 의 6 라벨 멀티라벨) 에서 ASL (Asymmetric Loss) 이 양성 희소 라벨의 학습을 눈에 띄게 도왔다. 같은 처방을 PII NER (33-class 토큰 분류) 에 적용하려다, 동작 조건 자체가 다르다는 걸 깨달았다. 이 글은 두 task 의 구조적 차이와, 어떤 손실 함수가 어떤 환경에 맞는지를 정리한다.

## 두 task 의 구조 — 한눈에

|                 | 유해콘텐츠 (멀티라벨 분류)                       | PII NER (토큰 분류)                          |
|-----------------|-----------------------------------------------|---------------------------------------------|
| 분류 단위        | 문장 1개                                       | 토큰 1개                                     |
| 라벨            | 6 라벨, 각각 0/1 **독립**                     | 33 라벨 (O + 16×BI) 중 **하나만**             |
| 출력 layer      | 6 sigmoid (독립)                              | 33-class softmax                             |
| 기본 손실        | BCE (Binary Cross-Entropy)                    | Cross-Entropy                                |
| imbalance       | 양성 희소 — sample 단위 (예: CRIME 양성 ~5%) | O 토큰 90 % 이상 — 토큰 단위                  |

겉으로 보면 둘 다 "라벨 imbalance" 문제처럼 보인다. 하지만 출력 layer 가 어떻게 라벨을 다루느냐가 손실 함수 적용 가능성을 결정한다.

## ASL 이 멀티라벨에서 통한 이유 — 칸별 독립

ASL 의 핵심은 세 가지다.

- **γ⁻ (쉬운 음성 억제)**: "이 문장은 안전" 처럼 모델이 자신 있게 0 으로 예측한 negative 의 loss 기여를 낮춘다.
- **γ⁺ (쉬운 양성 억제)**: 양성도 focusing — 너무 쉬운 양성은 덜 가중.
- **clip**: 극단적으로 쉬운 음성은 아예 무시.

이 장치들의 공통점은 **각 라벨의 확률을 독립적으로 본다**는 점이다. sigmoid 환경에서는 6 라벨이 각각 0/1 의 베르누이 분포 — CENSURE 가 양성이라고 SEXUAL 의 확률이 줄지 않는다. 칸 하나하나가 **각각 다른 baseline** 을 가지고, 각 칸에서 양성/음성의 비대칭이 따로 발생한다.

ASL 의 비대칭 처리 (양성에 γ⁺, 음성에 γ⁻) 는 정확히 이 "칸별 독립" 위에서 동작한다. 어떤 칸에서 양성이 희소하면 그 칸의 γ⁻ 가 negative bias 를 잡아준다. 칸 사이의 간섭이 없으니, 라벨마다 비대칭 정도가 달라도 따로따로 조정된다.

## PII NER 에서는 작동 환경이 다르다

PII NER 의 33 라벨은 한 토큰의 분류에서 **합이 1 인 단일 분포**가 된다. softmax 가 그 보장을 만든다. O, B-NAME, I-NAME, B-PHONE … 33 개의 칸은 서로 **상호의존적** — B-NAME 의 확률이 오르면 다른 32 개가 자동으로 줄어든다.

이 환경에서 ASL 의 γ⁻ 를 "O 라벨에 적용" 하는 식으로 옮겨봐도 의도가 깨진다.

- O 토큰의 loss 를 줄인다 → 다른 32 개의 확률이 자동으로 올라간다 (softmax 합 보존). 어떤 PII 라벨로 갈지는 제어가 안 된다.
- 양성에 γ⁺ 를 적용한다 → 양성이 무엇인지 자체가 33 개 중 하나로 결정되므로, "한 칸의 양성/음성" 이라는 개념 자체가 사라진다.

쉽게 말하면 ASL 의 비대칭 처리는 **칸이 독립적이어야** 의미가 있다. softmax 의 칸들은 독립이 아니다.

## softmax 환경에서의 imbalance 처리

토큰 분류의 imbalance — O 가 90 % 이상 — 는 다른 처방을 쓴다.

- **클래스 가중치**: O 의 loss weight 를 낮추고 PII 라벨의 weight 를 높인다. 단순하지만 효과적.
- **Focal Loss**: γ 로 쉬운 예 (대부분 O) 의 기여를 낮춘다. softmax 와 호환되는 비대칭 처방.
- **CRF 디코딩**: 토큰별 분류 위에 시퀀스 일관성 (B 뒤에는 같은 카테고리의 I 만) 을 강제. CRF 는 loss 가 아니라 디코딩 단계의 처방이다.

우리 PII NER 에서는 Cross-Entropy + CRF 로 충분히 학습이 되고 있고, hard testset F1 이 0.91 대를 안정적으로 유지한다. ASL 을 굳이 옮길 동기가 없다.

## 정리

- 같은 "imbalance" 라는 단어로 묶이지만, 멀티라벨 분류와 토큰 분류는 출력 layer 가 완전히 다르다.
- ASL 은 sigmoid + 칸별 독립을 전제로 만든 처방이다. 멀티라벨 분류에선 강력하지만 softmax 환경에는 그대로 옮길 수 없다.
- softmax 의 imbalance 는 클래스 가중치·Focal Loss·CRF 같은, 분포가 단일이라는 사실에 맞춘 도구들이 답이다.

손실 함수는 모델의 출력 layer 와 짝을 이룬다. 다른 task 의 처방을 가져올 때 가장 먼저 봐야 할 건 출력 layer 가 같은 구조인지다.
