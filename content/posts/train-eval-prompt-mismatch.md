## 증상: 점수가 이상하게 낮다

한국어 entity 추출용 LLM 을 LoRA 로 파인튜닝하고 평가를 돌렸다. 그런데 특정 카테고리의 recall 이 납득이 안 될 만큼 낮게 나왔다. 학습 데이터에는 분명히 잘 나오는 패턴인데, 평가에서는 모델이 자꾸 헛다리를 짚었다.

처음엔 의심 순서가 이랬다:

1. 데이터가 부족한가? → 충분했다
2. 학습이 덜 됐나? → loss 는 잘 떨어졌다
3. 모델이 작은가? → 다른 카테고리는 잘 잡았다

다 아니었다.

## 범인: 학습과 평가의 프롬프트가 달랐다

학습 데이터를 만든 코드와 평가를 돌리는 코드의 **system prompt 가 서로 달랐다.**

학습 데이터 생성 시 system prompt:

```
다음 텍스트에서 A(...), B(...), C(...) 3가지만 찾아 JSON 으로 반환하세요.
```

평가 코드의 system prompt:

```
다음 텍스트에서 아래 16가지 유형을 모두 찾아 JSON 으로 반환하세요.
A, B, C, D, E, F, ... (16개)
추가로 각 항목에 reason 필드를 한국어로 작성하세요.
```

즉 **3개 카테고리만 찾도록 학습된 모델에게, 평가에서는 16개 카테고리 + reason 필드를 요구**하고 있었다.

## 왜 점수가 깎였나

모델 입장에서 생각해보면 당연하다.

- 학습할 때는 "이 3개만 신경 써" 라고 배웠는데
- 평가할 때 갑자기 "16개 다 찾고 이유도 써" 라고 하니
- 학습한 적 없는 카테고리를 억지로 시도하다가 엉뚱한 라벨을 뱉거나
- 출력 형식(reason 필드)이 학습 분포와 달라 파싱이 흔들렸다

실제로 예측 결과를 까보니, 학습한 적 없는 카테고리로 잘못 분류한 출력이 섞여 있었다. 모델이 "프롬프트가 16개를 요구하니까 뭔가 더 찾아야 하나?" 하고 혼란스러워한 흔적이었다.

## 교훈: 평가는 학습과 같은 조건이어야 한다

너무 당연한 말 같지만, 코드가 분리돼 있으면 이게 쉽게 어긋난다.

- 학습 데이터 생성 스크립트 (`prepare_data.py`)
- 평가/추론 스크립트 (`eval.py`)

이 둘이 각자 system prompt 를 정의하고 있으면, 한쪽만 수정했을 때 조용히 mismatch 가 생긴다. 에러도 안 난다. 그냥 점수만 낮아진다.

### 해결

평가 코드의 프롬프트를 학습 데이터와 **글자 단위로 일치**시켰다. system prompt 와 user template 둘 다.

```python
# 학습 데이터의 system prompt 를 그대로 복사해서 검증
train_system = json.loads(open(train_file).readline())["messages"][0]["content"]
assert train_system == EVAL_SYSTEM_PROMPT  # 일치 확인
```

수정 후 해당 카테고리 점수가 정상으로 돌아왔다.

## 정리

- **LLM 파인튜닝에서 프롬프트는 "코드 상수"가 아니라 "학습된 입력 분포의 일부"다.** 평가에서 다른 프롬프트를 쓰면 distribution shift 가 생긴다.
- 학습/평가 프롬프트는 **한 곳에서 정의해서 공유**하는 게 안전하다. 양쪽에 복붙하면 언젠가 어긋난다.
- 점수가 이상하게 낮은데 데이터/모델/학습이 다 멀쩡해 보이면, **추론 시 모델에게 실제로 들어가는 입력**을 한 번 찍어봐야 한다. 학습 때 본 것과 같은지.

> 결국 모델은 아무 잘못이 없었다. 우리가 다른 질문을 던지고 있었을 뿐.
