## 조용한 폴백

개인정보 탐지의 평가 하네스는 모델 출력 위에 결정론 규칙 여러 개를 얹는다. 대화 안에서 이름을 추적하는 규칙, 기호로 끊은 이름을 다시 잡는 2차 패스 같은 것들이다. 이 규칙들은 전부 이렇게 감싸져 있었다.

```python
try:
    from pipeline.rules import scope_names
except ImportError:
    scope_names = None   # 모듈이 없으면 이 규칙은 건너뛴다
```

원래는 규칙이 아직 병합되지 않은 브랜치에서도 하네스가 돌게 하려는 장치였다. 시간이 지나 모든 규칙이 병합된 뒤에도 이 감싸기는 남았다. 이제 이 코드가 하는 일은 하나다. 모듈을 못 찾으면 에러 없이 그 규칙만 끈 채로 측정을 끝낸다. 숫자는 정상처럼 나온다.

## 실제 사고: 커밋된 적 없는 파일

다른 배포 환경에서 실제로 비슷한 일이 터졌다. 한 평가 스크립트가 저장소에 한 번도 커밋된 적이 없었다. 원인은 `.gitignore`의 한 줄이었다.

```
[Ss]cripts
```

앞에 `/`가 없는 패턴은 저장소 안의 모든 깊이에서 같은 이름의 경로에 걸린다. 그래서 다른 코드를 통째로 가져와 둔(벤더링) 트리 안의 `scripts/` 폴더까지 제외되고 있었다.

개발자의 로컬에는 파일이 있었으므로 테스트는 전부 통과했다. 문제는 저장소를 새로 클론하거나 컨테이너를 빌드할 때만 드러났다. 그쪽은 import 오류로 바로 멈췄다. 같은 일이 우리 하네스에서 생겼다면 감싸기가 오류를 받아내고, 규칙만 꺼진 수치가 조용히 나왔을 것이다.

## 측정 헤더에 켜진 규칙을 찍는다

수치를 보는 사람이 그 수치가 어떤 구성에서 나왔는지 알 수 있게 했다. 하네스가 시작할 때 규칙별 상태를 로그 첫머리에 찍고, 꺼진 규칙이 있으면 경고를 붙인다.

```
[rules] 결합 라우팅=ON · 대화 스코프=OFF · … · 음절 2패스=ON
[rules] ⚠ 꺼진 규칙 1개 — 이 수치는 그 상태의 값이다
```

이 출력은 별도 함수로 떼어 두고, 플래그 하나를 일부러 꺼서 경고가 실제로 나오는 것까지 확인했다. 경고 문자열이 코드에 있는지가 아니라, 그 상황에서 실제로 발동하는지를 본 것이다.

## CI에서 볼 것

이 일에서 얻은 점검 항목은 이렇다.

- 필수 구성 요소는 import 실패를 받아내지 않는다. 선택 기능일 때만 폴백을 두고, 폴백이 발동하면 실행 결과에 그 사실을 남긴다.
- 로컬에서 통과한 테스트는 "파일이 있는 상태"에서 통과한 것이다. 새로 클론한 디렉터리나 깨끗한 컨테이너에서 설치부터 테스트까지 돌려야 추적되지 않은 파일에 기대는 문제가 드러난다.
- `.gitignore`의 디렉터리 패턴은 의도한 위치에 앵커를 둔다(`/scripts/`). 어떤 파일이 왜 제외됐는지는 `git check-ignore -v <경로>`로 확인할 수 있다.
- 측정 결과에는 결과를 바꿀 수 있는 설정을 같이 기록한다. 같은 모델, 같은 데이터라도 켜진 규칙이 다르면 다른 숫자다.

## 정리

모듈이 없을 때 조용히 넘어가는 폴백은, 처음 만든 이유가 사라진 뒤에도 남아 측정을 오염시킬 수 있다. 에러 없이 나온 숫자는 의심받지 않는다. 그래서 수치를 낼 때는 그 수치가 어떤 구성에서 나왔는지를 같은 출력에 남기고, 구성이 기대와 다르면 크게 알리게 만든다.
