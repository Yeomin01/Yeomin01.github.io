## 이번 개선은 대부분 코드에 있었다

새 버전을 승격하면서 버전 카드에 이 문장을 넣었다. "체크포인트만 교체하면 안 된다." 그 주에 개선된 동작의 상당 부분은 모델 가중치가 아니라 정규식 규칙과 텍스트 정규화 코드에 있었다. 서빙 쪽에서 체크포인트 파일만 바꿔 끼우면 성능표의 숫자가 나오지 않는다.

탐지 결과를 만드는 것을 나열하면 이렇다.

| 구성 요소 | 바뀌면 |
|---|---|
| 모델 가중치 | 후보 스팬이 달라진다 |
| 보정 온도 | 신뢰도가 달라져 같은 임계값에서 다른 결과가 나온다 |
| 라벨별·단계별 임계값 | 어디서 자를지가 달라진다 |
| 정규식·정규화·후처리 규칙 코드 | 최종 스팬이 달라진다 |
| 2차 LLM 프롬프트와 정책 버전 | 무엇을 풀어 줄지가 달라진다 |

이 중 하나만 바꿔도 다른 시스템이다. 그래서 버전은 체크포인트가 아니라 이 묶음 단위로 남긴다.

## 버전마다 남기는 것

학습할 때마다 아래를 남기는 것을 규칙으로 두고 있다. 목적은 하나다. 로그와 설정만 보고도 "어떤 데이터로, 어떤 방식으로, 이전 대비 무엇을 바꿔, 어떤 베이스 모델로" 학습했는지를 복원할 수 있어야 한다.

설정 파일. 하이퍼파라미터와 경로는 코드에 하드코딩하지 않고 설정 파일에만 둔다. 설정 파일 맨 위에 이전 버전 대비 바뀐 점을 한 줄로 적는다. 베이스 모델은 출처가 드러나는 식별자로 적는다.

학습 로그 첫머리의 데이터 요약. 학습·평가 건수, 라벨 분포, 출처별 레코드 수를 항상 찍는다. 데이터 생성 스크립트도 생성 건수와 출처·언어 분포를 남긴다. 데이터를 바꾼 실험에서 "무엇이 들어갔는지"를 나중에 다시 계산하지 않아도 되게 하려는 것이다.

버전 카드. 레이어별 모델 기록 문서에 버전마다 카드를 추가한다. 실행 ID, 베이스 모델, 데이터 건수와 라벨 비율, 이전 대비 변경점, 변경 동기, 입력 표현과 손실, 결과(승격 게이트 통과 여부, 핵심 지표, 선택한 에폭), 배포 여부를 적는다. 바뀐 변수가 하나뿐인 실험이면 그 사실을 카드 첫머리에 쓴다. 승격하지 않은 버전도 카드를 남기고 이유를 적는다. 평가 데이터 오염으로 무효가 된 버전도 마찬가지다.

실행 폴더. 한 번의 학습 산출물은 실행 ID 폴더 하나에 모은다. 설정 사본, 평가 결과, 에폭별 체크포인트가 들어간다. 에폭별로 남기는 이유는 검증셋 최고점이 아니라 분포 밖 평가로 에폭을 고르는 경우가 있어서다.

## 큰 산출물은 DVC로

실행 폴더 하나가 수 GB다. 배포한 버전의 실행 폴더는 파일 169개, 8.1GB였다. 이런 산출물은 git에 넣지 않고 DVC로 관리한다. git에는 내용 해시와 크기, 파일 수가 적힌 작은 포인터 파일만 커밋하고, 실제 파일은 팀 스토리지의 DVC 원격에 올린다. 지금 저장소에는 학습 데이터 폴더와 배포한 실행 폴더, 결합기 산출물 등을 가리키는 포인터가 17개 있다.

이렇게 두면 배포한 버전을 재현할 때 명령 하나로 그 시점의 산출물을 받을 수 있다.

```bash
dvc pull <레이어>/out/logs/<실행ID>.dvc
```

포인터가 커밋 이력에 남으므로, 어느 코드 커밋이 어느 산출물과 짝이었는지도 git 이력으로 따라갈 수 있다.

## 넘겨주는 묶음

서빙 쪽에 넘길 때는 체크포인트, 보정 값, 임계값 표, 그 표를 만든 산출 경로 정보, 평가 재현용 데이터를 한 묶음으로 넘기고, 파일 목록과 해시를 적은 매니페스트를 같이 둔다. 받는 쪽은 매니페스트로 묶음이 온전한지 확인한다.

값을 다시 산출해서 묶음을 교체할 때는 이전 판을 지우지 않고 날짜를 붙여 보존한다. 임계값을 서빙과 다른 경로로 뽑았다는 것을 알게 돼 다시 산출한 일이 있었다. 그때도 이전 판을 남겨 두었기 때문에, 어떤 값이 언제 왜 바뀌었는지를 비교해 설명할 수 있었다.

배포 정본이 어느 실행인지는 설정 폴더의 포인터 파일 하나에 적는다. 서빙 구성이 둘 이상이면 포인터도 구성별로 따로 둔다. 한 구성의 포인터를 다른 구성의 새 모델로 덮어쓰면, 기존 구성이 어떤 모델로 돌고 있는지 알 수 없게 된다.

## 정리

모델 한 버전의 동작은 가중치, 보정, 임계값, 규칙 코드, 2차 프롬프트가 함께 만든다. 그래서 버전은 이 묶음 단위로 남기고, 넘길 때도 묶음으로 넘긴다. 큰 파일은 DVC로 관리하고 git에는 포인터를 남긴다. 그리고 바뀐 점과 그 이유는 학습할 때 바로 적는다. 나중에 복원하려고 하면 대개 이미 기억이 흐려져 있다.
