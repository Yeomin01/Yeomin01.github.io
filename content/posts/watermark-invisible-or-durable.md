## 이어서

모델을 온프레미스로 내보낼 때 "이 사본이 어디로 나갔는지" 확인할 수단이 필요했다. 네 가지를 만들어 재봤는데, 원하던 조합이 원리상 불가능하다는 게 드러났다.

## 순서를 서명으로 쓸 수 있다

신경망 은닉층은 **유닛 순서를 바꿔도 결과가 같다.** 여러 사람이 각자 계산해 합치는 구조라, 앉는 자리를 바꿔도 합계가 같은 것과 같다. 앞 층의 행과 뒤 층의 열을 같은 순서로 옮기면 함수가 수학적으로 동일하다.

그러면 **그 자리 배치 자체를 서명으로 쓸 수 있다.** 겹치지 않는 유닛 쌍 (a, b) 를 열쇠로 정해두고 "치환 후 a 가 b 보다 앞이면 1" 로 읽는다.

![은닉 유닛 순서를 바꿔도 출력은 같다. 그 순서가 서명이 되지만 정렬하면 사라진다](/images/wm_permutation.svg)

실측에서 200만 문장 판정이 **한 건도 안 바뀌었다.** 출력 차이는 부동소수점 덧셈 순서에서 오는 1e-06 뿐이었다. 512자까지 대가 없이 들어가고 심는 데 3초다.

## 그런데 줄만 세우면 사라진다

문제도 같은 성질에서 나온다. 공격자가 유닛을 **아무 기준으로 정렬**하면 순열 정보가 없어진다. 우리 열쇠를 알 필요도 없다. 동점 없는 기준으로 정렬하니 서로 다른 두 사본이 **해시까지 일치**했고, 모델 정확도는 99.96% 로 소수점까지 그대로였다.

일반화하면 이렇다. **함수를 보존하는 가중치 변환은 군을 이루고, 군에는 정규형이 있다.** 순열과 스케일링이 대표적이다. 정규형이 존재한다는 건 **누구나 그리로 보낼 수 있다**는 뜻이고, 그 순간 군 안에서의 위치 정보는 전부 날아간다.

다만 정렬은 흔적을 남긴다. 정상 모델은 유닛 번호와 가중치 크기의 상관이 0.01~0.02 인데 정렬당한 모델은 정확히 1.0 이다. 누구 것인지는 못 밝혀도 **의도적으로 세탁했다는 사실은 증명된다.**

## 값에 심으면 반대 문제가 생긴다

값을 건드리는 쪽은 정렬에 안 흔들린다. 대신 **판정이 바뀐다.** 200만 문장에서 30~39건이 뒤집혔다. 전부 임계값 근처, 모델이 원래 확신하지 못하던 입력이었지만 0 은 아니다.

"판정을 거의 안 건드리면서 값에 심을 수 없나" 싶어 한 가지를 더 만들었다. 문장 표현을 주성분 분해하면 **데이터가 거의 쓰지 않는 방향**이 나온다. 거기로만 가중치를 밀면 로짓이 안 움직인다 — 같은 세기로 밀 때 로짓 변동이 111배 작았다.

## 조용한 곳은 지워지기도 쉽다

그런데 이게 흔한 최적화에 깨졌다. 이유가 명확했다.

![데이터 에너지는 방향이 뒤로 갈수록 급락하지만 양자화 오차는 모든 방향에 고르게 퍼져 있다](/images/wm_signal_noise.svg)

**데이터 에너지는 앞쪽 방향에 몰려 있는데 양자화 오차는 방향을 안 가린다.** 하위 120방향에 데이터는 0.03% 뿐인데 int4 오차는 16.7% 가 들어온다 — 균등분포값 15.6% 와 사실상 같다. 신호가 잡음보다 31배 작으니 양자화 한 번에 묻힌다.

밀어내는 양을 100배로 키우니 양자화·프루닝을 견뎠다. 대신 뒤집힘이 0 에서 7건이 됐다. 배수를 1 → 5,000 으로 훑으니 **신호 · 내성 · 뒤집힘 셋이 한 방향으로 같이 움직였다.** 내성만 오르는 구간은 없었다. **손잡이가 하나다.**

## 계산

기호부터. 입력 문장이 인코더를 지나 나오는 은닉 표현이 `h ∈ R^d` (d=768), 분류기 가중치가
`W ∈ R^(C×d)` (C=클래스 수), 로짓이 `z = W h` 다. 판정은 이 `z` 하나로 갈린다.

**치환이 함수를 보존하는 이유.** 치환행렬 `P` 는 직교라 `PᵀP = I` 이고,
활성함수 `σ` 가 원소별이라 `σ(Pu) = P σ(u)` 가 성립한다.

```
W_in  ← P W_in
b_in  ← P b_in
W_out ← W_out Pᵀ

W_out Pᵀ · σ(P W_in x + P b_in)
  = W_out Pᵀ P · σ(W_in x + b_in)
  = W_out σ(W_in x + b_in)          ← 원래 함수와 동일
```

비트는 유닛 쌍의 앞뒤로 읽는다. `pos(u)` 를 치환 후 u 의 자리라 하면

```
b_k = 1[ pos(a_k) < pos(b_k) ]
```

**저에너지 방향은 SVD 로 찾는다.** 문장 n 개의 표현을 쌓은 `H ∈ R^(n×d)`, 평균 `μ` 에 대해

```
H − 1μᵀ = U Σ Vᵀ,     Σ = diag(s₁ ≥ … ≥ s_d)
방향 i 가 담는 에너지 비중 = s_i² / Σⱼ sⱼ²
```

실측에서 상위 10방향이 77.62%, 하위 120방향이 0.030% 였다. 한 가지 함정이 있다 —
`rank(H − 1μᵀ) ≤ min(n,d) − 1` 이라 **마지막 특이값은 구조적으로 0** 이다.
`s₇₆₈ = 1.16e-05` 로 바로 앞 `s₇₆₇ = 0.146` 의 1/12,562 였다. 이걸 모르고
`s₁/s₇₆₈` 를 쓰면 2.2×10⁷ 이라는 과장된 비를 얻는다. 실제는 `s₁/s₇₆₇ = 1,814` 다.

**변화를 그 부분공간에 가둔다.** 하위 m개 방향을 모은 `V_low ∈ R^(d×m)` 에 대해

```
ΔW = A V_lowᵀ,        A ∈ R^(C×m)      자유도 = C·m
Δz(h) = ΔW h = A (V_lowᵀ h)
```

괄호 안이 "이 문장이 그 방향에 얼마나 실렸나"이고, 그게 거의 0 이라 로짓이 안 움직인다.

**여기서 버그가 났다.** 위 식을 평균과 편차로 쪼개면

```
Δz(h) = A V_lowᵀ μ        ← 모든 문장에 공통 (사실상 편향 이동)
      + A V_lowᵀ (h − μ)  ← 문장마다 다른 부분
```

상한을 **중심화한 H** 로 재면 첫 항이 계산에서 빠진다. 그래서 상한을 지켰다고 믿은 판본의
실제 최대 로짓 변화가 4배 초과였다. 연속학습 문헌이 **비중심화** 공분산을 쓰는 이유가 이것이다.
실측으로도 저에너지 방향에서 변동분은 111배 줄지만 상수분은 6.6배밖에 안 줄었다.

**크기 상한.** 표본 최대 로짓 변화를 δ 로 묶고 배수 s 를 곱한다.

```
κ = min(1, δ / maxᵢ |Δz(hᵢ)|)
ΔW ← κ · s · ΔW
```

**비트를 심고 읽기.** 비밀 행렬 `X ∈ R^(B×Cm)`, 목표 비트 `bₖ`, 부호 `σₖ = 2bₖ − 1` 일 때

```
심기: min_A  Σₖ softplus(1 − σₖ ⟨Xₖ, vec(A)⟩) + λ‖A‖²
읽기: b̂ₖ = 1[ ⟨Xₖ, vec(A)⟩ > 0 ],   A = (W − W₀) V_low
```

부호 기반(방식 1)은 `A` 없이 `b̂ₖ = 1[⟨Xₖ, vec(W)⟩ > 0]` 이라 **원본이 없어도 읽힌다.**
저에너지는 `W₀` 가 필요하고, 치환은 원본 전체가 있어야 순서를 복원한다.

**글자로 되돌리기.** 36심볼이라 글자당 6비트, r중 반복 후 다수결.

```
b̃ⱼ = 1[ Σ_{t<r} b̂_{j+tL} ≥ ⌊r/2⌋+1 ]
c   = ALPHA[ Σ_{i<6} b̃_{6j+i} · 2^(5−i) ]
```

**신호 대 잡음.** 양자화 `Q` 를 걸었을 때 읽는 값이 얼마나 흔들리는가.

```
signal = medianₖ |⟨Xₖ, vec(A)⟩|
noise  = meanₖ   |⟨Xₖ, vec(A_q − A)⟩|,   A_q = (Q(W) − W₀) V_low
```

배수 1 에서 `0.0015` 대 `0.0467` 로 신호가 잡음보다 31배 작았다.
배수를 100 배 올리면 S/N 이 0.03 → 3.3 이 되면서 int4 를 견딘다.

**뒤집힘 기대값.** 임계값 근처 문장 밀도를 ρ(점수 1 구간당 문장 수)라 하면

```
E[뒤집힘] ≈ maxᵢ |Δpᵢ| × ρ
```

임계값 ±0.01 안에 200만 중 16건이 있었으니 ρ ≈ 800. 점수 변화를 1e-3 으로 묶으면
기대값이 200만 중 0.8건이다. 실제로 그 판본은 0건이었다.

## 넓게 보면

**지우기 어렵게 만드는 힘은 서명이 출력에 영향을 주는 부분과 얽혀 있다는 데서 나온다.** 영향이 0 이면 그 얽힘도 없어 떼어내기 쉽다. 이건 구현의 문제가 아니라 구조다.

그래서 실질적 최선은 **제거 방법이 서로 다른 방식을 겹쳐 쓰는 것**이다. 순서 기반은 정렬로, 값 기반은 스펙트럼 사영으로 지워지는데 두 공격은 전제가 다르다. 하나만 아는 공격자는 나머지를 못 지운다. 실제로 세 방식을 한 모델에 겹쳐 심어도 서로 간섭하지 않았다 — 건드리는 자리가 순서 · 미사용 파라미터 · 가중치 값으로 겹치지 않기 때문이다.

한 가지 더. **네 방식 모두 사전 공증 없이는 증거가 못 된다.** 워터마크를 심은 적 없는 깨끗한 모델에서 원하는 문자열을 읽어내는 열쇠를 몇 초 만에 만들 수 있다. 심는 시점에 열쇠 해시를 시각과 함께 고정해두지 않으면 "우리 열쇠로 서명이 나왔다"는 아무것도 증명하지 못한다.

## 메모

- 함수 보존 변환은 군을 이룬다. 정규형이 있으면 그 안의 위치 정보는 정규화 한 번에 사라진다.
- 조용한 부분공간에 숨기면 데이터에게 안 보이는 만큼 잡음에도 그대로 노출된다. 잡음은 방향을 안 가린다.
- 워터마크는 검증 전에 공증이 필요하다. 열쇠를 나중에 만들면 원하는 값이 나오게 맞출 수 있다.
